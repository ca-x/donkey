## Findings considered and deferred

- Serialize first-user administrator provisioning in SQLite rather than only
  an in-process mutex before supporting multiple Donkey processes against one
  database.
- Full foreign-key/CHECK-constraint table rebuild: valuable, but HIGH migration
  risk for v0.1 data. Do it after the migration fixture from plan 002 exists.
- Add explicit `sync_rule_id`/scheduled lineage so one copy job updates only
  the rule that created it; pair enqueue and schedule-cursor advance in one
  transaction.
- Add cache filesystem/index reconciliation and remove absolute cached paths;
  crash-safe orphan handling needs dedicated recovery fixtures.
- Split `image_tools.rs` into API/jobs/source/copy/export/filesystem modules:
  correct direction, but behavior-preserving extraction should follow plans 001
  and 003.
- Direct-vs-node `ImageSource` adapters: defer until proxy characterization
  tests protect manifest selection, digest checks, and shared-Blob behavior.
- Separate SQLite from NAS Blob storage and add online backup: document and
  implement after configuration compatibility is specified; do not silently
  relocate existing data.
- Bring detached background loops under a cancellable, waitable server
  lifecycle before promising graceful in-flight export/copy shutdown.
- Apple-style trigger-anchored desktop popovers and mobile sheets: useful polish,
  but lower leverage than fixing stale form state, destructive-action agency,
  accessibility preferences, and pending feedback.
